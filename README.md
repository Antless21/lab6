## Установка

Требуется Python 3.10 или новее. Все команды выполняются из папки проекта.

Скачать исходники через Git:

```bash
git clone https://github.com/Antless21/lab6.git
cd lab6
```

```bash
python -m venv .venv
```

Активировать окружение в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

В macOS / Linux:

```bash
source .venv/bin/activate
```

Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

Если команда `python` недоступна, используйте `python3` (macOS/Linux)
или `py` (Windows) при создании окружения.

## Запуск и демонстрация

### 1. Flask: форма и таблица

```bash
python flask_app.py
```

- Открыть <http://127.0.0.1:5000/>. Ввести `Александр` и нажать «Поздороваться».
  Результат: `Привет, Александр!`.
- Открыть <http://127.0.0.1:5000/students>. Таблица из трёх учебных записей
  формируется циклом Jinja2.
- Пустое имя и имя длиннее 50 символов отклоняются сервером с HTTP 400.
  Jinja2 экранирует HTML в имени.

### 2. FastAPI: JSON, база данных и чат

Во втором терминале активировать то же окружение и выполнить:

```bash
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

- JSON: <http://127.0.0.1:8000/api/info>.
- Swagger UI для выполнения запросов к базе: <http://127.0.0.1:8000/docs>.
- Чат: <http://127.0.0.1:8000/chat>.

JSON endpoint возвращает объект:

```json
{
  "message": "Привет, FastAPI!",
  "student": "Мовчан Александр Дмитриевич",
  "group": "221341",
  "variant": 2,
  "lab": 6
}
```

### Проверка базы данных

База `data/students.sqlite3` и таблица `students` создаются автоматически
при запуске FastAPI. Начальный список пуст. SQLite входит в стандартную
библиотеку Python, отдельный сервер базы данных не нужен.

В Swagger UI раскрыть `POST /api/students`, нажать **Try it out**,
ввести тело запроса и нажать **Execute**:

```json
{"name": "Александр Мовчан", "age": 20, "group_name": "221341"}
```

Возраст в примере условный. Скопировать `id` из ответа и использовать его
в следующих запросах.

| Метод | Адрес | Результат |
|---|---|---|
| POST | `/api/students` | Создать запись, HTTP 201 |
| GET | `/api/students` | Список записей, HTTP 200 |
| GET | `/api/students/{id}` | Одна запись, HTTP 200 |
| PUT | `/api/students/{id}` | Полностью заменить имя, возраст и группу, HTTP 200 |
| DELETE | `/api/students/{id}` | Удалить запись, HTTP 204 без тела |

Для PUT используется то же тело, что для POST. Несуществующий ID даёт HTTP 404,
ошибочный ввод — HTTP 422. Имя: 1–100 символов, группа: 1–30 символов,
возраст: целое число 1–120. Пробелы по краям строк удаляются.
SQL-запросы используют параметры `?`.

Остановить сервер сочетанием Ctrl+C и запустить снова: записи сохраняются.
Путь можно переопределить переменной окружения `LAB6_DB_PATH`.
Файл базы не включается в Git.

Таблица Flask использует отдельный учебный список: это самостоятельное
среднее задание. Данные SQLite доступны через FastAPI и Swagger UI.

### Проверка чата

1. Открыть <http://127.0.0.1:8000/chat> в двух вкладках браузера.
2. В первой войти как `Александр`, во второй — как `Анна`.
3. Отправить сообщение из любой вкладки: оно появится у обоих участников.
4. Нажать «Выйти» в одной вкладке. Второй участник сможет продолжить общение;
   вышедший участник может подключиться снова.

Клиент отправляет текстовые WebSocket-сообщения. Сервер рассылает всем
подключённым клиентам JSON с `type`, `name`, `text`, `time` (UTC).
Имя: 1–50 символов, сообщение: 1–1000 символов после удаления пробелов по краям.
Ошибки сообщений возвращаются только отправителю с `type: "error"`.
Неверное имя закрывает соединение с кодом 1008.
Браузер выводит сообщения через `textContent`.

Чат предназначен для одного процесса Uvicorn: запускать без `--workers`.
История сообщений не хранится в базе и не загружается новым участникам.
Для демонстрации достаточно одного компьютера и нескольких вкладок.

Локально проверено на Python 3.10.9: **25 тестов пройдено**, Ruff — без ошибок.
Также проверены запуск обоих серверов, HTTP-запросы и обмен сообщением

Тесты проверяют форму, HTML-экранирование, таблицу, JSON, CRUD, валидацию,

участникам, отключение клиента и ошибочные WebSocket-сообщения.
Используется временная база, данные рабочего приложения не затрагиваются.
GitHub Actions запускает проверки при push и pull request.
